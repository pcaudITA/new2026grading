The grading transition

2023 → G2026

The PCaudit grading system evolved: grades, codes, points, logic and photos. All 193 legacy codes were mapped one by one — and G2026 is now our default catalog for every client program.

The upgrade

What G2026 brings

Finer resolution

Severity tiers per component — minor, medium, major — so the record captures exactly what the auditor sees, and the report reads exactly as the device is.

One vocabulary

A single code set across laptops, mobiles, printers, servers and everything in between. Learn it once; it means the same thing on every bench and on every report line.

Five bands, sharper meaning

D now means precisely "critical", and a dedicated E scrap flag gives end-of-life units a place of their own on the scale.

A richer record

Measured battery bands, precisely named locks, a point weight on every code — more verified facts per unit than the record has ever carried.

Points

The point map: a severity gauge on every code

Entirely new in G2026. Every code carries a numeric weight, and the weight tells you at a glance how heavy a finding is, even within the same band.

1–9A-class facts
e.g. minor blemish 4
10–99B-class
e.g. medium blemish 25
100–999C-class
e.g. major port errors 100
1000D-class
critical, one is enough

How to read it: two B-codes are not equal — a 25 weighs more than a 10, and the weights make that visible. Three jobs: gauge severity when reading a report line, break ties on genuinely borderline grading calls (the weights point to the likelier side), and feed the future automation of the conformity check. One non-job, stated plainly: points are not the grading decision. Units are graded by the accumulation rules below — never by adding up numbers.

Codes

One vocabulary for every device

The quietest change is the one that saves the most memory: the device dialects are gone.

CABA1 MCBA1 PCBA1 → CABA1

Where 2023 had one scratch code for computers, another for mobiles, another for printers, G2026 has one. A cabinet blemish is a cabinet blemish whether it sits on a server or a smartphone. Auditors learn the vocabulary once — and it means the same thing on every line of every report.

The front/rear doctrine, written into the catalog

OldNewBand · points
one code — "light scratched/dented/chipped case" CABA1 Minor blemishes (front)A · 4
CABA2 Minor blemishes (rear)A · 2

Front and rear were always judged differently in an auditor's head — the front is what a buyer sees. Now the codes themselves know the difference, at every severity tier — and notice the weights agree: front wear weighs double.

Displays: broken screens are a D — a departure from the old codes

OldNewBand · points
"heavy scratched/stained/chipped screen" — lived in the C twenties DSPA20 Medium display damageC · 100
DSPA31 Major display damageD · 1000

The line is fracture. Any crack, chip or break in the glass — however small, however pretty the rest of the panel — is major display damage: grade D. Under 2023, heavy screen damage graded C; G2026 raises the bar — update the instinct. Scratches still grade by the fingernail test; broken is broken.

Batteries: now a measurement

"Battery health degraded" was a single entry. Now batteries are a measurement, and each band is its own code:

  • BATF1 capacity ≥80% — a positive, A-class fact, now part of the record
  • capacity in the 70s — a B-class fact; lower bands — C-class, each coded separately
  • not charging, battery unswappable — what it always really was: D critical

The habit that changes: battery health is recorded on every unit — always. Aiken's automatic battery test passing is not the record: the pass only means the unit cleared the threshold. The capacity band still gets its code, starting with BATF1 for a healthy battery. A measured battery is a fact worth money — write it down like any other fact.

Merged & retired: the catalog, modernized

Merged

Distinctions that never changed the outcome are gone. A dead laser and a dead trigger meant the same thing in practice — now both are OTHF31 "Barcode scanner faulty". Missing processor, missing motherboard → OTHM31 "Missing essential parts".

Retired

Six codes left the catalog entirely — among them the whole optical-drive family (cosmetic, tray, noise, defective, missing). The catalog now reflects the hardware that actually reaches the bench.

Logic

The rule that changed: accumulation

Most of the table did not move. The change is rule three — where the old footnote became the law.

Findings2023G2026
A-wear, rearstays Astays A — rear micro-wear never lifts a grade, no matter how much
A on the front ×3becomes Bbecomes B — light wear on what the user looks at, three times over, is no longer like-new
B ×3mechanically C
footnote: "correct to the better grade if the overall impression is good"		B/C border — sellability decides the side. The call is the auditor's: autonomous, judged as a buyer would
C, any numberstays Cstays C — C never accumulates: five significant defects and one are both a C
one DDD — one is enough, whatever else is true

Read the old footnote again — it was doing the real work all along. G2026 promotes it to the rule and trusts the auditor's judgment. When a call is genuinely in doubt: the manual first, then the QC manager. A short Aiken note on close calls helps QC follow the reasoning — a tool, not a duty.

One laptop, two systems

The unit: three medium blemishes on lid and palmrest (B-class each) + the usual micro-scratches on the base (rear A-wear).

2023G2026
Rear wearrecorded, ignoredrecorded, ignored — same
Three front Bsmechanical C, with the footnote applied at the auditor’s discretionB/C border — the auditor looks at the whole unit as a buyer would
VerdictC (typically)clean screen, solid keyboard, presentable at arm's length → B. Genuinely tired → C. The auditor decides.

Same unit — but the side is now a judged call, not mechanics. If the call feels genuinely even, the point weights are the sanctioned tiebreaker — and lingering doubt goes to the manual, then to the QC manager.

Locks & data

Locked units: the statistical codes are gone

OldNewEffect
arrived locked 243LCKL1 Unlockedthe event is recorded; the grade is untouched
password locked 308LCKL39 Unable to unlock + the specific lock codeD — and the claim-back process runs from the specific code

Every lock now has a name: BIOS password LCKL30, drive password LCKL31, Apple ID LCKL33, Google FRP LCKL34, MDM LCKL35, Intune/Autopilot LCKL36, Knox LCKL37, custom splash LCKL38. Naming the lock precisely is what makes the claim-back fast.

Photos

The record changed shape

The doctrine: comprehensive photos of the unit's overall state at the Tag — every face. Those photos are the record; every coded defect must be findable in them. Close-ups are a tool, not a duty: when the Tag set cannot make one important defect unambiguous, a clarifying close-up is added. The old habit of one photo per defect code is retired — we photograph the truth of the unit, not a checklist.

For our customers

What you will see in reports

  • More precise lines: tiered codes instead of generic ones — "major port errors", not "broken port".
  • A severity gauge on every line: the point weight tells you how heavy each finding is, even between two codes of the same band.
  • Comparable across all device types: one vocabulary means the same code means the same thing on every asset class.
  • Measured batteries: capacity bands as recorded facts, including healthy batteries.
  • Named locks: the exact lock type on every locked unit — which is what makes claim-back faster.
  • Judged borderline grades: B/C border units are decided by auditor judgment against sellability — close calls may carry a short explanatory note.
  • Full traceability: the complete old-to-new mapping table exists for every legacy code — nothing was dropped silently.
